# namefix

파일·폴더 이름의 **자소 분리(NFD)** 와 **URL 인코딩(`%XX`)** 을 정리하는 Windows 도구입니다. 탐색기에서 항목을 오른쪽 클릭해 실행하거나, 터미널에서 명령으로 실행합니다.

| 정리 전(디스크에 저장된 이름) | 정리 후 |
|---|---|
| `웨비나 자료.pdf` — 화면에는 같아 보이지만 초성·중성 낱자로 저장된 이름(NFD, macOS에서 옮겨 온 파일) | `웨비나 자료.pdf` — 완성형 글자로 저장(NFC) |
| `%ED%95%9C%EA%B8%80%20%EB%AC%B8%EC%84%9C.pdf` | `한글 문서.pdf` |
| `%25ED%2595%259C.txt` (이중 인코딩) | `한.txt` |

자소 분리 이름은 화면에서는 정상으로 보이는 경우가 많습니다. 하지만 검색, 정렬, 압축, 업로드, 다른 프로그램에서 파일을 열 때 문제가 생길 수 있습니다.

## 설치와 제거

요구 사항은 Windows 10 또는 11, .NET Framework 4.x입니다. Windows에 기본으로 포함되어 있으므로 별도 SDK 설치가 필요하지 않습니다. 설치와 제거 모두 관리자 권한이 필요 없습니다.

```bat
install.bat      :: 빌드 → %LOCALAPPDATA%\Programs\namefix 에 복사 → 탐색기 메뉴 등록
uninstall.bat    :: 탐색기 메뉴 등록 해제 → 설치 폴더 삭제 (변경 기록은 남김, 두 단계가 모두 성공해야 종료 코드 0)
```

소스를 고친 뒤 `install.bat`을 다시 실행하면 새 버전으로 덮어씁니다.

## 탐색기에서 사용하기

설치하면 현재 사용자의 오른쪽 클릭 메뉴에 다음 항목이 추가됩니다.

| 오른쪽 클릭 위치 | 메뉴 | 동작 |
|---|---|---|
| 파일(여러 개 선택 가능) | 파일명 정리 (자소 분리·URL 인코딩) | 선택한 파일의 이름을 정리합니다. |
| 폴더 | 폴더 이름 정리 (자소 분리·URL 인코딩) | 선택한 폴더 자신의 이름만 정리합니다. |
| 폴더 | 폴더와 하위 항목 이름 모두 정리 | 폴더 이름과 그 안의 모든 파일·폴더 이름을 정리합니다. |
| 폴더 안 빈 공간 | 이 폴더의 파일명 정리 (자소 분리·URL 인코딩) | 현재 폴더 바로 아래 항목의 이름을 정리합니다. |

> [!NOTE]
> Windows 11의 새 오른쪽 클릭 메뉴에서는 **추가 옵션 표시**(또는 `Shift+F10`, `Shift`+오른쪽 클릭) 아래에 나타납니다.

결과는 다음과 같이 표시됩니다.

- 문제 없이 이름을 바꾸면 대화상자를 띄우지 않습니다. 바뀐 이름이 탐색기에 바로 보입니다.
- 충돌이나 오류가 있으면 항목별 사유와 변경 기록 위치를 대화상자로 알립니다.
- 바꿀 이름이 없으면 "정리할 이름이 없습니다"라고 알립니다.
- 파일을 여러 개 선택해도 결과 대화상자는 한 번만 뜹니다.

## 명령줄에서 사용하기

설치 폴더(`%LOCALAPPDATA%\Programs\namefix`)나 빌드 폴더(`bin\`)의 `namefix.exe`를 실행합니다.

```text
namefix [옵션] <경로>...

  -n, --dry-run     이름을 바꾸지 않고 바뀔 이름만 보여 줍니다.
  -r, --recursive   폴더와 모든 하위 항목의 이름을 정리합니다.
  -c, --children    폴더 자신은 두고 안의 항목만 정리합니다(-r과 함께 쓰면 모든 하위 항목).
      --no-url      URL 인코딩(%XX)을 풀지 않습니다.
      --no-nfc      자소 분리(NFD)를 합치지 않습니다.
      --gui         결과를 대화상자로 보여 주고, 동시에 실행된 요청을 한 번에 처리합니다.
  -q, --quiet       항목별 결과와 합계를 출력하지 않습니다(충돌·오류는 출력).
  -v, --verbose     바뀌지 않은 항목도 출력합니다.
      --register    탐색기 오른쪽 클릭 메뉴를 현재 사용자에게 등록합니다.
      --unregister  탐색기 오른쪽 클릭 메뉴 등록을 해제합니다.
  -h, --help        도움말을 출력합니다.
  -V, --version     버전을 출력합니다.
```

| 지정 방식 | 처리 범위 |
|---|---|
| `namefix <폴더>` | 폴더 자신의 이름 |
| `namefix -r <폴더>` | 폴더 자신과 모든 하위 항목 |
| `namefix -c <폴더>` | 폴더 바로 아래 항목(폴더 자신은 제외) |
| `namefix -c -r <폴더>` | 모든 하위 항목(폴더 자신은 제외) |
| `namefix <파일>` | 파일 이름(옵션과 관계없음) |

종료 코드는 `0`(정상, 바꿀 것이 없는 경우 포함), `1`(충돌·오류 있음), `2`(사용법 오류)입니다.

```powershell
# macOS에서 복사한 폴더 전체를 미리 확인한 뒤 정리
namefix -n -r "D:\from-mac"
namefix -r "D:\from-mac"
```

## 정리 규칙

이름 한 개를 다음 순서로 변환합니다.

1. **URL 디코딩**: `%XX` 연속을 UTF-8 바이트로 보고 한 문자씩 풉니다. 이중·다중 인코딩은 더 바뀌지 않을 때까지 반복해서 풉니다.
2. **NFC 정규화**: 자소 분리(NFD) 문자를 완성형(NFC)으로 합칩니다. 인코딩된 바이트가 자소 분리 자모인 경우도 함께 처리됩니다.
3. **고정점까지 반복**: 1~2단계 결과를 다시 변환해도 바뀌지 않을 때까지 반복합니다. 그래서 정리한 이름을 다시 정리해도 더 바뀌지 않습니다.

다음 경우에는 원래 이름을 유지합니다.

| 경우 | 예 | 결과 |
|---|---|---|
| `%` 뒤가 16진수 두 자리가 아님 | `100% 완료.txt`, `50%OFF.txt` | 그대로 |
| UTF-8로 해석할 수 없는 바이트 | `%FF%FE.txt`, `abc%E3.txt` | 그대로 |
| 파일 이름에 쓸 수 없는 문자로 풀림 | `a%2Fb.txt` (`/`) | 해당 `%XX`만 유지 |
| 풀면 Windows에서 쓸 수 없는 이름 | `name%20`(끝 공백), `CON%2Etxt`·`COM%C2%B9.txt`(예약 이름 `CON`, `COM¹`) | URL 디코딩 생략, NFC만 적용 |

예약 이름은 [Microsoft 이름 규칙 문서](https://learn.microsoft.com/windows/win32/fileio/naming-a-file)(2024-08-28 판)를 따릅니다. 대상은 `CON`, `PRN`, `AUX`, `NUL`, `COM1~9`, `COM¹~³`, `LPT1~9`, `LPT¹~³`이며, 확장자가 붙은 경우도 포함합니다. `COM0`·`LPT0`은 예약 이름이 아니므로 디코딩합니다.
| `+` 기호 | `C++ guide.txt` | 공백으로 바꾸지 않음 |

## 안전장치

- **덮어쓰지 않음**: 바꿀 이름의 항목이 이미 있으면 충돌로 보고하고 두 항목 모두 그대로 둡니다. NTFS는 자소 분리 이름과 완성형 이름을 서로 다른 이름으로 저장하므로 같은 폴더에 둘 다 있을 수 있습니다. 같은 파일의 하드 링크나 대소문자만 다른 항목이어도 별개 항목이므로 충돌로 처리합니다. 새 이름으로 찾은 항목이 원본 자신일 때만 이름을 바꿉니다(정규화를 구분하지 않는 macOS SMB 공유 등).
- **미리 보기와 실제 결과 일치**: `--dry-run`도 같은 새 이름으로 바뀔 예정인 항목끼리의 충돌을 찾아 보고합니다.
- **요청한 항목만 처리**: 요청 시점에 항목이 있었는지와 원본의 식별자(볼륨·파일 ID)를 기록합니다. 처리 시점에 경로가 없어졌거나 다른 항목으로 바뀌었으면, 식별자로 원본의 현재 경로를 찾아 처리합니다. 원본이나 상위 폴더의 이름이 먼저 정리된 경우도 포함합니다. 로컬 NTFS에서는 파일 ID로 직접 열어 찾습니다. 파일 ID로 열 수 없는 SMB 공유에서는 경로의 각 단계를 원래 이름이나 정리된 이름으로 따라가며 식별자가 같은 항목을 찾습니다. 요청 당시 없던 경로, 요청 경로에 새로 생긴 다른 항목, 이름만 대응하는 다른 항목은 처리하지 않고 오류로 보고합니다. 하드 링크가 여러 개인 파일은 같은 파일 ID를 가진 디렉터리 항목이 여럿이라 요청한 항목을 정할 수 없습니다. 이 경우 두 탐색 방법 모두 원본으로 인정하지 않고 오류로 보고합니다.
- **같은 항목은 한 번만**: 같은 항목을 다른 경로 표기(`D:\work`와 `D:\WORK`, 정션 별칭)로 여러 번 지정해도 한 번만 처리합니다. 같은 파일의 별개 하드 링크나 대소문자를 구분하는 폴더의 대소문자만 다른 항목은 서로 다른 항목으로 처리합니다.
- **저장된 이름 기준**: 입력한 경로의 대소문자가 디스크에 저장된 이름과 달라도(`A%20X.TXT`로 지정한 `a%20x.txt`), 저장된 이름을 정리합니다(`a x.txt`).
- **경로가 깨지지 않는 순서**: 처리할 항목의 경로를 링크를 모두 따라간 실제 위치로 확정해 둡니다. 정션 별칭이나 연쇄 정션을 거쳐 지정해도 마찬가지입니다. 그 뒤 하위 항목부터 이름을 바꿉니다. 그래서 다른 항목(폴더, 정션)의 이름이 먼저 바뀌어도 처리할 경로가 끊기지 않습니다. 결과와 변경 기록에는 실제 위치의 경로가 표시됩니다.
- **다시 처리해도 안전**: 같은 요청을 두 번 처리해도 결과가 같습니다. 이미 정리된 원본은 "이미 정리됨"으로 기록하고 오류로 보고하지 않습니다.
- **동시 실행 직렬화**: 같은 사용자의 namefix 실행이 겹치면 실제 이름 변경 단계를 차례로 실행합니다. 나중 실행은 앞선 실행의 결과를 보고 처리합니다.
- **부분 실패 격리**: 다른 프로그램이 사용 중인 파일처럼 이름을 바꿀 수 없는 항목은 오류로 보고합니다. 나머지 항목은 계속 처리합니다.
- **링크 안으로 들어가지 않음**: 심볼릭 링크와 정션 폴더 안의 항목은 처리하지 않습니다. 링크 자체의 이름은 정리합니다. 링크 폴더를 직접 지정해 하위 항목 정리(`-r`, `-c`, 하위 포함 메뉴)를 실행하거나 링크 폴더 안에서 빈 공간 메뉴를 실행해도 하위 항목은 바꾸지 않고 오류로 알립니다. 이 경우 링크가 가리키는 실제 폴더에서 실행합니다.
- **대소문자 구분 폴더 지원**: 대소문자를 구분하도록 설정한 NTFS 폴더에서 대소문자만 다른 두 항목도 각각 처리합니다.
- **변경 기록**: 바꾼 항목, 충돌·오류 항목과 실행 요약을 `%LOCALAPPDATA%\namefix\namefix.log`에 남깁니다. 탭으로 구분한 UTF-8 텍스트이며, 1MB를 넘으면 `namefix.log.1`로 넘깁니다. `--dry-run`은 기록하지 않습니다.

```text
<시각>  RENAMED   <이전 경로>  <새 경로>
<시각>  CONFLICT  <이전 경로>  <새 경로>  같은 이름의 항목이 이미 있습니다.
<시각>  SUMMARY   source=gui  pid=…  inputs=20  renamed=20  conflict=0  error=0  unchanged=0  already=0
```

## 빌드와 테스트

```bat
build.bat                                         :: bin\namefix.exe, bin\namefixw.exe 생성
pwsh -NoProfile -File tests\run-tests.ps1         :: 회귀 테스트(임시 폴더·격리 레지스트리 사용, 실제 메뉴 등록 변경 없음)
pwsh -NoProfile -File tests\e2e-shell.ps1         :: 탐색기 메뉴 연동 검증(install.bat 실행 후)
```

- 빌드에는 Windows에 포함된 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`를 사용합니다. 이 컴파일러는 C# 5 문법까지만 지원하므로 문자열 보간(`$"..."`), `?.`, `nameof` 같은 이후 문법을 쓰지 않습니다.
- 테스트는 PowerShell 7 이상이 필요합니다. PowerShell의 `-eq`·`-contains`는 문화권 비교를 사용하므로 NFD와 NFC를 같은 문자열로 볼 수 있습니다. 그래서 테스트는 이름을 서수(Ordinal) 비교로 판정합니다.
- 테스트용 환경 변수는 다음과 같습니다.

  | 변수 | 용도 |
  |---|---|
  | `NAMEFIX_LOG` | 로그 경로 |
  | `NAMEFIX_NO_DIALOG=1` | 대화상자 끄기 |
  | `NAMEFIX_COLLECT_MS` | 다중 실행 집계 대기 시간(100~5000, 기본 500ms) |
  | `NAMEFIX_TEST_ACK_DELAY_MS` | 수집자가 처음 받은 요청의 ACK를 늦게 보냄(ACK 시간 초과 재현) |
  | `NAMEFIX_TEST_DISABLE_OPEN_BY_ID=1` | 파일 ID로 열기(`OpenFileById`)를 쓰지 않음(SMB 공유처럼 대체 탐색만으로 원본을 찾는 경로 재현) |
  | `NAMEFIX_TEST_PAUSE_MS` | 요청 경로·식별자를 확정한 뒤 처리 전에 지정한 시간(1~60000ms)만큼 멈춤(요청과 처리 사이의 경로 변경 재현) |
  | `NAMEFIX_TEST_CRASH_POINT`, `NAMEFIX_TEST_CRASH_MARKER` | 수집자를 처리 전(`before-process`) 또는 처리 후 완료 알림 전(`after-process`)에 한 번 강제 종료(복구 재현). 표시 파일을 새로 만들 수 있을 때만 종료 |
  | `NAMEFIX_TEST_REGISTRY_ROOT` | 메뉴 등록 위치 변경(`HKCU\Software\namefix-test*` 아래만 허용, 그 밖의 값이면 실패, 제거 테스트용) |

- SMB 공유 시험은 로컬 관리 공유(`\\localhost\C$`)에 접근할 수 있을 때만 실행합니다.
- 회귀 테스트는 실제 메뉴 등록을 건드리지 않습니다. 제거 테스트는 격리 레지스트리 경로와 임시 `LOCALAPPDATA`를 사용합니다. 실행 파일이 격리 경로를 지원하지 않는 이전 빌드이면 해당 구간을 실행하지 않고 실패로 표시합니다.

## 동작 구조

```text
탐색기 메뉴 ──(항목마다 실행)──▶ namefixw.exe --gui "<경로>"  ×N
                                     │
                    먼저 실행된 1개가 수집자(수집자 뮤텍스·수명 뮤텍스 소유)
                    나머지는 이름 있는 파이프로 요청 전달 → ACK 수신 후
                    "완료 이벤트" 또는 "수집자 종료"를 기다림
                                     │
                 마지막 요청 후 500ms 동안 새 요청이 없으면 수집 종료
                                     ▼
       실행 잠금 → 깊은 경로부터 이름 변경 → 변경 기록 → 완료 이벤트 켜기
       → 수명 뮤텍스 해제 → 문제 있을 때만 대화상자
```

- 각 프로세스는 경로를 자기 작업 폴더 기준 절대 경로로 확정합니다. 그 뒤 요청 ID, 변환 옵션(`--no-url`, `--no-nfc`), 원본 식별자를 함께 보냅니다. 여러 메뉴가 동시에 실행되어 한곳에 모여도 요청마다 자기 경로와 옵션으로 처리합니다. 절대 경로로 확정할 수 없는 경로는 보내지 않고 그 프로세스에서 오류로 보고합니다.
- 보낸 프로세스는 수집자가 처리를 마쳤다는 완료 신호를 받아야 종료합니다. 완료 신호 없이 수집자가 끝나면(비정상 종료 포함) 같은 요청을 다시 보내거나 직접 처리합니다. 그래서 요청은 적어도 한 번 처리됩니다.
- 수집자는 요청마다 충돌·오류가 있었는지 함께 알립니다. 각 프로세스의 종료 코드는 자기 요청의 결과를 따릅니다(대화상자는 수집자가 모아서 한 번 보여 줍니다).
- 다시 처리하는 경우에도 이름 정리가 멱등이고 실행 잠금으로 직렬화되므로, 결과가 같고 오류가 나지 않습니다.
- 파이프 연결, 쓰기, 읽기 대기에는 모두 제한 시간이 있습니다. 수집에 20초 안에 참여하지 못하면 자기 요청을 직접 처리합니다. 처리 완료 대기에는 제한 시간이 없습니다. 수집자가 살아 있는 동안 기다리고, 수집자가 끝나면 곧바로 깨어납니다.

| 파일 | 역할 |
|---|---|
| `src/NameNormalizer.cs` | 이름 문자열 변환(URL 디코딩, NFC, Windows 이름 유효성) |
| `src/Renamer.cs` | 처리 범위 확장, 충돌 판정, 이름 변경 |
| `src/Collector.cs` | 동시에 실행된 인스턴스의 요청 집계(뮤텍스, 이름 있는 파이프, 완료 이벤트) |
| `src/ExecutionLock.cs` | 이름 변경 단계의 사용자 단위 실행 잠금 |
| `src/ShellIntegration.cs` | 탐색기 메뉴 등록·해제(HKCU) |
| `src/RenameLog.cs` | 변경 기록 |
| `src/NativeMethods.cs` | 항목 식별자(파일 ID) 조회와 식별자로 현재 경로 찾기, 폴더 대소문자 구분 조회, 입출력 취소, 탐색기 갱신 알림, DPI 설정 |
| `src/Program.cs` | 진입점, 옵션 해석, 결과 출력 |

`.bat` 파일은 ASCII로만 작성합니다. `cmd.exe`는 배치 파일을 OEM 코드 페이지로 읽기 때문에 UTF-8 한글이 들어가면 다음 줄이 깨질 수 있습니다.

## 제한 사항

- Windows 11 새 오른쪽 클릭 메뉴의 첫 화면에는 나타나지 않습니다. 첫 화면에 표시하려면 서명된 패키지(MSIX sparse package)와 `IExplorerCommand` 구현이 필요합니다.
- 전체 경로가 260자를 넘는 항목은 오류로 보고됩니다.
- 호환용 자모(`ㅎㅏㄴ`, U+3131~)로 따로 입력된 이름은 유니코드 정규화 대상이 아니므로 합치지 않습니다.
- 탐색기 메뉴는 설치한 사용자에게만 등록됩니다.
- 탐색기는 선택한 항목마다 프로세스를 하나씩 실행합니다. 수백 개 이상을 한꺼번에 선택하면 느려질 수 있으므로, 이때는 폴더 빈 공간 메뉴(이 폴더의 파일명 정리)나 폴더의 하위 포함 메뉴를 쓰십시오.
