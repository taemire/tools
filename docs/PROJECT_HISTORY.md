## 2026-11-09: namefix 추가 (파일명 자소 분리·URL 인코딩 정리)

### 배경
- macOS에서 옮겨 온 파일은 이름이 자소 분리(NFD) 형태로 저장되어, Windows에서 검색·정렬·업로드·다른 프로그램 연동 시 문제가 생김. 화면에서는 정상 이름과 구분되지 않음.
- 브라우저·메일로 받은 파일 이름이 `%ED%95%9C...`처럼 URL 인코딩된 상태로 저장되는 경우가 있음.
- 요구사항: 탐색기 오른쪽 클릭 메뉴로 선택 항목의 이름을 자동 정리.

### 작업 내용
- `namefix/` 신설: `src/`(C# 7개 파일), `build.bat`, `install.bat`, `uninstall.bat`, `tests/`, `README.md`
- 콘솔용 `namefix.exe`와 탐색기용 `namefixw.exe`(콘솔 창 없음)를 같은 소스에서 빌드
- 탐색기 메뉴 4종(HKCU) 등록·해제 기능(`--register`, `--unregister`)
- 다중 실행 집계(뮤텍스 + 이름 있는 파이프 + ACK), 변경 기록, 충돌 시 건너뜀

### 의사결정
- **컴파일러**: .NET SDK가 없는 환경에서도 빌드할 수 있도록 Windows 기본 `.NET Framework 4.x` `csc.exe`(C# 5)를 사용.
- **메뉴 방식**: 정적 명령줄 동사(`HKCU\Software\Classes`)를 채택. Windows 11 새 메뉴 첫 화면 표시(`IExplorerCommand` + 서명된 sparse package)는 서명·배포 부담 때문에 제외하고 "추가 옵션 표시" 아래 노출로 정리.
- **다중 선택**: 명령줄 동사는 항목마다 프로세스를 실행하므로, 대화상자가 여러 번 뜨지 않도록 첫 프로세스가 요청을 모아 처리. `MultiSelectModel=Player`로 15개 초과 선택 시에도 메뉴 표시.
- **안전 우선**: 충돌 시 자동 번호 붙이기 대신 건너뛰고 보고. 금지 문자로 풀리는 `%XX`는 유지하고, 풀면 쓸 수 없는 이름(끝 공백, 예약 이름)이면 URL 디코딩을 생략하고 NFC만 적용.
- **배치 파일 ASCII 유지**: `cmd.exe`가 배치 파일을 OEM 코드 페이지로 읽어 UTF-8 한글이 다음 줄을 깨뜨릴 수 있으므로 `.bat`은 영문 주석만 사용.

### Codex 교차 리뷰 1차 지적 반영
- **링크 범위 이탈(높음)**: 정션을 직접 지정해 `-r`/`-c`로 실행하면 링크 대상 안까지 바뀌던 문제 → 시작 폴더가 재분석 지점이면 하위 처리를 거부하고 오류로 보고.
- **수집자 예외(높음)**: 연결 직후 끊긴 클라이언트로 수집자가 종료되어 받은 요청까지 유실될 수 있던 문제 → 연결 단위로 예외를 격리하고 수집한 요청 보존, `Main`에 최상위 예외 처리 추가.
- **요청별 옵션(중간)**: 집계된 요청에 수집자의 `--no-url`/`--no-nfc` 옵션이 적용되던 문제 → 옵션을 요청마다 직렬화.
- **재전송 중복(중간)**: ACK 시간 초과 후 재전송된 요청이 두 번 처리될 수 있던 문제 → 요청 ID, 수집자 내 중복 제거, 뮤텍스로 보호한 처리 이력 파일로 수집자 간 중복 제거.
- **로그 교체 경쟁(중간)**: 동시 교체로 이전 기록을 잃을 수 있던 문제 → 로그 경로별 뮤텍스로 직렬화하고 `.1` 교체를 `File.Replace`로 원자화.
- **하드 링크(중간)**: 같은 파일의 별개 하드 링크를 같은 항목으로 판정해 링크 하나가 사라지던 문제 → 부모 폴더에 서수 비교로 같은 별개 항목이 있으면 충돌 처리.
- **대소문자 구분 폴더(중간)**: 대소문자만 다른 항목이 중복 제거로 누락되던 문제 → 서수 비교로 중복 제거.
- **예약 이름(중간)**: `COM0`, `LPT0`, `COM¹~³`, `LPT¹~³` 추가.
- **비동기 작업 회수(낮음)**: 시간 초과로 포기한 `Begin*`의 완료를 회수하도록 `End*` 호출.
- **제거 결과(낮음)**: `uninstall.bat`이 메뉴 키 삭제와 폴더 삭제를 확인하고 실패 시 종료 코드 1 반환.

### Codex 교차 리뷰 2차 지적 반영
- **재전송 중복(1차 미해소)**: 처리 이력 파일 방식은 이력 저장 실패·수집자 비정상 종료 경계에서 중복이나 유실이 남았음. 통신만으로는 정확히 한 번을 보장할 수 없으므로 설계를 바꿈 → 전달은 최소 한 번으로 두고, 이름 정리를 멱등하게 만들어 중복 처리를 무해화. 처리 이력 파일 제거.
  - URL 디코딩을 3회 제한에서 고정점 반복으로 변경(`Normalize(Normalize(x)) == Normalize(x)`).
  - 요청 경로가 없고 정리된 이름의 항목이 있으면 "이미 정리됨"(`Unchanged`, `AlreadyNormalized`)으로 처리하고 정리된 경로로 이어서 처리.
- **로그 교체(1차 미해소)**: `Local\` 뮤텍스는 세션별로 분리되므로 `Global\`로 변경.
- **하드 링크(1차 미해소)**: 대소문자만 다른 하드 링크를 놓치던 문제 → 파일 ID 비교를 없애고, 새 이름으로 검색한 실제 항목이 원본 자신일 때만 허용.
- **비동기 작업 회수(1차 미해소)**: 스트림을 닫은 뒤 `End*`를 호출하면 .NET Framework가 닫힌 핸들 검사에서 예외를 던져 회수하지 못함 → 핸들이 열린 상태에서 `CancelIoEx`로 취소한 뒤 `End*` 호출, 그다음 닫기.
- **제거 결과(1차 미해소)**: `reg query` 실패를 "키 없음"으로 오인할 수 있었음 → 레지스트리 해제를 항상 `namefix.exe --unregister`로 수행하고, 해제 후 잔존 키를 검증.
- **상대 경로(신규, 높음)**: 집계된 상대 경로가 수집자의 작업 폴더 기준으로 해석되던 문제 → 보내기 전에 절대 경로로 확정.
- **쓰기 제한 시간(신규, 중간)**: 읽지 않는 수집자에게 동기 쓰기가 막히던 문제 → 제한 시간이 있는 비동기 쓰기.
- **미리 보기 충돌(신규, 중간)**: 같은 새 이름으로 바뀔 예정 항목끼리의 충돌을 놓치던 문제 → 예정 이름을 폴더별로 예약(폴더의 대소문자 구분 설정 반영).

### Codex 교차 리뷰 3차 지적 반영
- **처리 보장(2차 미해소)**: ACK 직후 수집자가 처리 전에 종료하면 요청을 복구할 주체가 없었음 → 보낸 쪽이 ACK 후 바로 종료하지 않음. 수집자의 완료 이벤트나 수명 뮤텍스 해제·버려짐을 기다리고, 완료 신호 없이 수집자가 끝나면 같은 요청을 다시 처리. 보낸 쪽이 파이프 연결을 붙잡지 않으므로 선택 항목 수가 파이프 인스턴스 한도의 영향을 받지 않음.
- **상대 경로(2차 미해소)**: 절대 경로 확정에 실패하면 상대 경로를 그대로 보냈음 → 그 경로는 보내지 않고 자기 프로세스에서 오류로 보고.
- **미리 보기 예약(2차 미해소)**: 폴더 예약 키가 경로 문자열이라 `D:\Work`/`D:\work`를 다른 폴더로 봤음 → 폴더 식별자(볼륨·파일 ID)로 예약.
- **"이미 정리됨" 오인(신규, 높음)**: 이름만 대응하는 다른 항목을 이전 처리의 결과로 간주했음 → 요청 시점 원본 식별자를 기록하고 같을 때만 인정. 처음부터 없던 경로는 오류.
- **전체 변환 멱등성(신규, 중간)**: NFC가 결합 문자를 합치면 다음 변환에서 디코딩 결과가 달라졌음 → 디코딩·유효성 검사·NFC 전체를 고정점까지 반복.
- **동시 중복 실행(신규, 중간)**: 같은 트리를 동시에 처리하면 한쪽이 원본을 찾지 못해 오류가 났음 → 이름 변경 단계를 사용자 단위 실행 잠금(`Global\namefix-execute-<SID>`)으로 직렬화.
- **테스트 격리 경로(신규, 중간)**: 잘못된 값이면 실제 레지스트리로 되돌아갔음 → 값이 있는데 허용 범위가 아니면 실패.
- **예약 이름(신규, 낮음)**: 1차 리뷰 제안으로 넣은 `COM0`·`LPT0`이 Microsoft 공식 목록(2024-08-28 판)에 없음을 확인하고 제거.
- 이 과정에서 수정 전 바이너리로 새 테스트를 실행해 실제 메뉴 등록이 `bin\` 경로로 덮어써진 일이 있었음. `install.bat`으로 복원했고, 테스트가 실행 파일의 격리 경로 지원 여부를 먼저 확인하도록 보호 장치를 추가함.

### Codex 교차 리뷰 4차 지적 반영
- 3차 지적 8건은 모두 해소로 판정됨.
- **경로 교체(신규, 높음)**: 요청 경로가 존재하면 식별자 검사를 건너뛰어, 원본이 정리된 뒤 같은 경로에 새로 생긴 항목을 처리할 수 있었음 → 경로가 있어도 요청 시점 식별자와 비교하고, 다르면 식별자로 원본을 찾아 처리.
- **상위 폴더 변경(신규, 중간)**: 마지막 이름만 정리해 찾았으므로 상위 폴더 이름이 바뀐 요청을 복구하지 못했음 → `OpenFileById`와 `GetFinalPathNameByHandle`로 식별자에서 현재 경로를 직접 찾음(하드 링크가 여러 개면 거부).
- **정션 경로 예약(신규, 중간)**: 폴더 예약 키가 링크 자체의 식별자였음 → 링크를 따라간 실제 폴더의 식별자 사용.
- **넘긴 요청의 종료 코드(신규, 중간)**: 넘긴 요청이 충돌·오류로 끝나도 보낸 쪽이 0을 반환했음 → 결과에 요청 출처를 붙이고, 문제 이벤트로 요청별 결과를 돌려줌. 종료 코드는 각 프로세스 자기 요청의 결과를 따름.
- **실행 잠금(참고)**: `Global\` 이름을 만들 수 없으면 `Local\` 이름으로 대체.
- 새 테스트 5건은 이전 빌드로 실행해 4건이 실패함(red)을 확인한 뒤 구현을 검증함. 나머지 1건은 이전 동작으로도 맞는 경우임.

### Codex 교차 리뷰 5차 지적 반영
- 4차 지적 4건은 모두 해소로 판정됨.
- **요청 당시 없던 경로(신규, 높음)**: 원본 부재와 식별자 조회 실패를 모두 빈 식별자로 저장해, 처리 전에 같은 경로에 생긴 항목을 처리할 수 있었음 → 요청 시점 존재 여부(`Existed`)를 따로 기록하고 없던 경로는 오류로 확정.
- **SMB 공유 복구(신규, 중간)**: `OpenFileById`가 SMB를 지원하지 않아, 이미 정리된 요청을 "항목 없음"으로 보고했음. 로컬 관리 공유(`\\localhost\C$`)로 실제 재현함 → 경로의 각 단계를 정리된 이름·원래 이름으로 따라가며 식별자가 같은 항목을 찾는 대체 탐색 추가.
- **경로 표기 별칭(신규, 중간)**: 같은 항목을 `D:\work`/`D:\WORK`나 정션 별칭으로 함께 지정하면 중복 처리되어 허위 충돌·오류가 났음 → "실제 부모 폴더 식별자 + 저장 이름"으로 대상 중복 제거(하드 링크·대소문자 구분 폴더의 별개 항목은 유지).
- 테스트 정리 단계에서 SMB 시험 직후 폴더 삭제가 일시적으로 실패하는 경우가 있어 재시도를 추가함.
- 새 테스트 6건(SMB 2건 포함) 가운데 5건이 수정 전 빌드에서 실패함(red)을 확인함. 나머지 1건은 로컬 NTFS 대체 탐색 시험으로, 테스트 지점이 구현되기 전이라 기존 경로로 통과했음.

### Codex 교차 리뷰 6차 지적 반영
- 5차 지적 3건은 모두 해소로 판정됨.
- **대체 탐색의 하드 링크 오인(신규, 높음)**: 하드 링크는 파일 ID가 같아, 대체 탐색이 요청하지 않은 다른 링크를 원본으로 인정할 수 있었음 → 대체 탐색도 링크가 여러 개인 파일은 거부(직접 열기와 같은 규칙).
- **정션 별칭과 처리 순서(신규, 중간)**: 경로 문자열 깊이로 순서를 정해, 정션으로 지정한 하위 항목보다 실제 경로로 지정한 부모를 먼저 바꿨음 → 링크를 따라간 실제 경로 깊이로 순서 결정.
- **저장 이름(신규, 중간)**: 입력 표기의 대소문자를 그대로 변환해 결과 이름의 대소문자가 바뀌었음 → 대상 경로의 마지막 이름을 저장 이름으로 바꿔 처리.
- 새 테스트 3건이 수정 전 빌드에서 모두 실패함(red)을 확인함.

### Codex 교차 리뷰 7차 지적 반영
- 6차 지적 3건은 모두 해소로 판정됨.
- **처리 순서(신규, 중간 2건)**: 드라이브 루트 바로 아래 폴더와 자식의 계산 깊이가 같아지는 문제, 경로 중간의 정션 자체가 대상일 때 그 정션을 먼저 바꾸는 문제가 있었음. 깊이 비교로는 두 경우를 함께 막을 수 없으므로 위상 정렬로 변경함 → 대상 경로의 각 상위 구성요소를 디렉터리 항목 키로 확인하고, 그 항목이 다른 대상이면 경로를 가진 쪽을 먼저 처리함. 깊이 계산은 루트를 뺀 구성요소 수로 통일하고, 실제 경로 깊이 계산(`RealDepthCalculator`)은 제거함.

## 2026-01-13: PDF 페이지 번호 체계 개선 (Isolated Counter Strategy)

### 배경
- **이슈**: PDF 생성 시 목차(TOC)가 2페이지(ii)로 표시되고, 본문이 3페이지(3)로 표시되는 문제 발생 (연속된 물리 페이지 번호가 노출됨).
- **원인**: Headless Browser 기반 렌더러가 `div`와 같은 DOM 요소 상의 `counter-reset`을 무시하고 물리적 페이지 흐름을 유지함.

### 해결 방안
- **카운터 격리 전략 (Isolated Counter Strategy)** 도입:
  1.  단일 `page` 카운터를 폐기하고, **`page-toc`**와 **`page-main`**으로 분리.
  2.  `@page frontmatter` 스코프에서는 `page-toc`만 증가.
  3.  `@page main` 스코프에서는 `page-main`만 증가.
  4.  각 섹션 진입 시 해당 카운터가 자연스럽게 1부터 시작되도록 유도.

### 결과
- **목차**: 로마자 **i**부터 시작 (물리 2페이지라도 논리 1페이지).
- **본문**: 아라비아 숫자 **1**부터 시작 (물리 3페이지라도 논리 1페이지).
- **산출물**: `d:/wdata/dev/tools/docs/PDF_PAGE_NUMBERING_TROUBLESHOOTING.md` (기술 회고록) 작성.

   - **점선 패턴(Dot Leader)**: `......` 등의 패턴이 많으면 목차로 판단
   - **최소 텍스트 길이**: 일정 길이(700자) 이상의 실질 데이터가 본문 페이지에 있어야 함

2. **동적 스킵 계산**:
   - 페이지 2부터 스캔하여 `isBodyPage`가 `true`가 될 때까지를 목차로 인식
   - 자동 감지 실패 시 기본값 3(표지 1+목차 2)으로 폴백
